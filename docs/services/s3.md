# S3 design

**State:** Current. **Next goal:** stored checksums and access policy subsets.

## Feature checklist

- [x] Create, list, inspect, tag, and delete buckets with partition-wide name uniqueness.
- [x] Put, get, head, delete, and list objects with metadata and upload checksum validation.
- [x] Handle conditional object requests and one byte range on GetObject and HeadObject.
- [x] Enforce bucket owner and region boundaries for path-style and supported virtual-hosted requests.
- [x] Multipart — `CreateMultipartUpload`, `UploadPart`, `ListParts`, `CompleteMultipartUpload`, `AbortMultipartUpload`, and upload listing. Uploads and parts remain separate from visible objects; completion validates part number, ETag, ordering, and minimum nonfinal part size, then atomically installs one object.
- [x] Notifications — Put/Get bucket notification configuration with validated destinations, event types, and prefix/suffix filters (overlaps rejected, `s3:TestEvent` sent). After a successful object commit, object-created/removed events go to SQS, SNS, Lambda, or EventBridge through provider calls outside the transaction. Multipart completion emits one event.
- [x] Copy and tagging — `CopyObject` within and between the caller's buckets (metadata and tagging directives, source preconditions, `ObjectCreated:Copy` events) and object tags (`Put/Get/DeleteObjectTagging`, `x-amz-tagging` on writes, `x-amz-tagging-count` on reads), stored in the object's metadata record.
- [x] Presigned URLs — Query-string SigV4 with `X-Amz-Expires` up to 7 days, verified with an unsigned payload; expired URLs answer `AccessDenied`.
- [x] Versioning — `Put/GetBucketVersioning` (`Enabled`, `Suspended`), `ListObjectVersions` with key and version ID markers, delete markers, and `versionId` on reads, deletes, copies, and tagging. The current version stays in the object records, so `ListObjectsV2` is unchanged; each key's history record holds older versions and delete markers newest first. Suspended writes and deletes replace the null version.
- [ ] Remaining object and access features — Stored checksum retrieval, signed aws-chunked payloads, and ACL/policy subsets with an explicit account identity model.

## State and integration

Path-style and supported virtual-hosted requests share a partition-wide bucket
name index. Bucket metadata records owner and creation region; object bytes and
metadata are committed together in the regional store. Bucket tagging,
Put/Get/Head/DeleteObject, CopyObject, object tagging, ListObjectsV2, versioning, checksums
on upload, conditional requests, a single byte range on Get/Head, multipart
uploads, and presigned URLs exist. A
completed multipart object is limited to 64 MiB. Unsupported modeled headers
and subresources fail explicitly.

Bucket names remain partition-wide while objects remain in the bucket owner’s
region. `GetObject` with a range returns 206 and `Content-Range`; ranged HEAD
returns only adjusted length. Multipart parts do not appear in object listing
or trigger notifications. Upload metadata and parts persist across restarts;
completion removes them in the same transaction that installs the object.
The current request and store path buffers objects;
larger uploads need streaming or bounded temporary storage before lifting the
64 MiB limit. REST XML status, headers, and errors come from generated bindings
and the shared codec.

## Acceptance checks

The SDK integration checks cover create, upload, part and upload listing,
invalid completion, abort, persistence restart, copies, object tags,
presigned GET and PUT URLs (including expiry), and versioning (version reads,
delete markers, version deletes that promote the next version, suspended null
versions, paged version listings, and version-aware notifications). Extend them with account
and region isolation, list paging boundaries, and AWS wire fixtures. Test notification
payloads, filters, failed targets, cross-account/region rejection, and
persistent restart. Repeat object tests with path and virtual-host addressing.
